# 打磨阶段细分改动包 — 2026-10-15

配套上位机：KRLmonitor（本仓库 `main`/`codex/global-polish-program`）

## 一、改了什么

把**打磨阶段**里的动作按"一次完整打磨"拆开，让上位机能显示：

```
空走（走到焊缝 k 的预备位） → 预备位 → 打磨（各道 + 补充） → 抬起（回预备位） → 空走（到焊缝 k+1）
```

**检测阶段完全不改**（保持 `-(k)` 一个整体）。

## 二、改动原则（安全约束）

1. **只改 `PassNo = ...` 赋值行**，不动任何运动指令（`SPTP/LIN/PTP`）、不动速度/力控参数、不动点位。
   → 机器人轨迹与原来**逐字节一致**，不可能走错位置。
2. `PassNo` 是只写的全局 INT（KRL 侧只赋值、从不读取判断），改它不影响程序分支。
3. 文件保持原样：**纯 ASCII + LF**，无 BOM，末尾无空行（与现场版本一致）。
4. 只做"替换 9 行 + 新增 3 行"，共 12 行/文件，可用 `original/` 一键回退。

## 三、编码约定（新增部分）

| PassNo | 含义 |
|---|---|
| `-(40+k)` | **走到焊缝 k 的打磨预备位**（下到 Pk4，Z=+40 抬高位） |
| `-(50+k)` | **打磨后抬起**（从打磨位回 Pk4） |
| `-(20+k)` | **空走/转移**：走到焊缝 k 的预备位（启用原预留值） |
| 正数 `n` | 打磨第 n 道（不变） |
| `-(10+k)` | 打磨阶段·道间返回（不变） |
| `-(k)` / `-(100+k)` | 检测阶段（不变） |

细磨（XiMo）如需同样拆分，编码整体 +100：`-(140+k)` / `-(150+k)` / `-(120+k)`（本次未改细磨，见第六节）。

## 五、上线步骤

1. **先升级上位机 exe**（识别 `-(40+k)`/`-(50+k)` 的版本）。旧 exe 也能安全运行：这两个值会被当作"未标记"显示，不会产生假道次。
2. 用 WorkVisual 打开工程库，用本包的两个 `.src` 覆盖 `KRC\R1\MinShi261010\` 下同名文件，**编译**（F7）确认无错误。
3. 下载到控制器（本次改动不涉及 EKI 配置、`$config.dat`、`sps.sub`，**不需要冷启动**）。
4. 现场验证：
   - 跑一件，上位机焊缝卡片应出现"预备位 / 打磨 / 抬起 / 空走"；
   - 点选某一条焊缝 → 曲线只显示这一条焊缝的 空走→预备→打磨→抬起，不混入别的焊缝；
   - 机器人轨迹与改动前一致（只有 `PassNo` 变量变化，无运动差异）。

## 六、回退

用 `original/` 下的两个 `.src` 覆盖回去、重新编译下载即可，无需改上位机。
